لایهٔ امن اتصال ربات تلگرام آهنگ‌بان به داده‌های واقعی وردپرس، همراه با وب‌هوک داخلی برای هاست اشتراکی.

== پیش از نصب یا ارتقا ==
اعتبارنامه‌ها در صورت وجود ابتدا از محیط PHP خوانده می‌شوند؛ اگر هاست امکان تعریف متغیر محیطی برای LSAPI/PHP را نداشته باشد، مدیر سایت می‌تواند آن‌ها را از فرم اختصاصی افزونه وارد کند. مقادیر فرم در گزینه‌های WordPress ذخیره می‌شوند و در صفحه دوباره نمایش داده نمی‌شوند؛ این روش نسبت به نگه‌داری در محیط PHP امنیت پایین‌تری دارد و نسخه‌های پشتیبان دیتابیس ممکن است شامل آن‌ها باشند.

* `AHANGBAN_API_TOKEN`: دقیقاً ۶۴ رقم hex تصادفی؛ اگر سرویس Python از API استفاده می‌کند باید با مقدار هم‌نام در `.env` خصوصی آن یکسان باشد.
* `AHANGBAN_BOT_TOKEN`: توکن BotFather.
* `AHANGBAN_BOT_SECRET`: Secret وب‌هوک، ۱ تا ۲۵۶ نویسه از حروف انگلیسی، عدد، `-` و `_`؛ مقدار ۶۴رقمی hex توصیه می‌شود.
* `AHANGBAN_TRUSTED_PROXY_IPS`: اختیاری؛ IP/CIDR پراکسی‌های مورداعتماد برای خواندن هدرهای IP.

فایل `.env` فقط برای سرویس Python است و WordPress آن را خودکار نمی‌خواند. اگر از محیط PHP استفاده می‌کنید، متغیرهای بالا را در handler موردپشتیبانی هاست تنظیم کنید؛ در غیر این صورت از فرم اعتبارنامه‌های افزونه استفاده کنید. Secretها را در Git یا گفتگو منتشر نکنید.

== نصب ==
1. ZIP افزونه را در پیشخوان وردپرس → افزونه‌ها → افزودن → بارگذاری افزونه نصب/جایگزین کنید.
2. در منوی «آهنگ‌بان API»، اعتبارنامه‌ها را یا در محیط PHP تنظیم کنید یا در فرم اختصاصی افزونه وارد و ذخیره کنید؛ صفحه فقط وضعیت را نشان می‌دهد و مقدار Secretها را دوباره چاپ نمی‌کند.
3. شناسهٔ ادمین، یوزرنیم ربات، حالت اجرا و در صورت نیاز کانال را از همان صفحه تنظیم کنید. برای هاست اشتراکی حالت وب‌هوک را انتخاب کنید؛ Python polling روی VPS است و با وب‌هوک برای یک Bot Token هم‌زمان اجرا نمی‌شود.
4. در حالت وب‌هوک روی «ثبت وب‌هوک در تلگرام» بزنید؛ اگر از وب‌هوک به polling می‌روید، نخست وب‌هوک قبلی را حذف کنید. سپس در تلگرام `/start` را امتحان کنید.

== قابلیت‌ها ==
* تماس با endpoint ثابت Telegram با TLS و بدون redirect؛ Token و متدهای API پیش از درخواست اعتبارسنجی می‌شوند تا false rejection در اعتبارسنجی URL بعضی هاست‌ها رخ ندهد.
* تشخیص اتصال Telegram از پیشخوان: getMe و getWebhookInfo؛ خطای انتقال/cURL/SSL و پاسخ HTTP تلگرام با حذف توکن و Secret نمایش داده می‌شود.
* تنظیم متن شروع و راهنما، تعداد نتایج آهنگ و هنرمند در صفحه و نمایش دکمه‌های منوی شروع از پیشخوان.
* تنظیم روشن/خاموش‌بودن پیش‌نمایش ویس کانال، انتخاب مدت ۱۵/۳۰/۴۵/۶۰ ثانیه و متن تکمیلی مشترک کپشن دستی/خودکار.
* REST اختصاصی با جست‌وجوی فارسی، فهرست هنرمندان، کارت اثر، جدیدترین و محبوب‌ترین‌ها.
* API عمومی Health حداقلی است؛ فقط `status: ok` را برمی‌گرداند.
* خروجی API فقط آثار منتشرشدهٔ موسیقی را در بر می‌گیرد؛ نوشتهٔ عادی یا محتوای خصوصی برگردانده نمی‌شود.
* جست‌وجو/صفحه‌بندی محدود است؛ پردازش UTF-8 بدون الزام به افزونهٔ PHP `mbstring` کار می‌کند.
* کش جزئیات آهنگ و نمایهٔ سبک هنرمندان؛ تصویر هنرمند فقط برای صفحهٔ درخواستی resolve می‌شود.
* مرتب‌سازی آثار هنرمند بر اساس عنوان پیش از صفحه‌بندی در SQL انجام می‌شود.
* ارسال صوت/ویدیو: دریافت مستقیم Telegram، سپس fallback امنِ محدود به ۴۹ MiB؛ پیوند واقعی در صورت شکست.
* اعتبارنامهٔ Telegram در درخواست‌های HTTP هیچ redirectی را دنبال نمی‌کند؛ ارسال فایل timeout مبهم را بی‌خطر retry نمی‌کند.
* اتصال اختیاری کانال با WP-Cron؛ انتشار خودکار خاموش است و نوشته‌های معمولی نادیده گرفته می‌شوند.
* کپشن کانال با نام واقعی WordPress، هشتگ فارسی از taxonomy هنرمند، لینک صفحهٔ رسمی و شناسهٔ @Ahangban_ir ساخته می‌شود؛ دو دکمهٔ شیشه‌ای ربات و سایت روی پست و ویس قرار می‌گیرند.
* پس از پست، نمونه‌ای از فایل واقعی `music128` (یا `music320`) به شکل Telegram Voice Note با reply به همان پست ارسال می‌شود؛ مدت ۱۵/۳۰/۴۵/۶۰ ثانیه و روشن/خاموش‌بودن آن از پیشخوان قابل تنظیم است (پیش‌فرض ۶۰ ثانیه). ساخت آن به FFmpeg دارای `libopus` و `proc_open` نیاز دارد؛ نبود این قابلیت ویس را متوقف می‌کند اما پست اصلی ارسال می‌شود.
* انتشار دستی پست از پنل ادمین Telegram با جست‌وجو/شناسه، پیش‌نمایش و تأیید؛ از کانال تنظیم‌شده در WordPress استفاده می‌کند و مستقل از ارسال خودکار است.
* پنل تلگرام: آمار، سلامت، پاک‌سازی cache، مسدودسازی، broadcast دسته‌ای و انتشار دستی پست.
* جدول‌های آماری/صف فقط در دیتابیس موجود WordPress هستند؛ دیتابیس موازی برای داده‌های سایت ساخته نمی‌شود.

== امنیت ==
* محیط PHP اولویت دارد؛ در نبود آن، اعتبارنامه‌ها می‌توانند از فرم مدیر و `wp_options` خوانده شوند. گزینه‌ها autoload نمی‌شوند و فیلدهای رمزواژه دوباره نمایش داده نمی‌شوند، اما مقدارها در دیتابیس رمزنگاری نشده‌اند.
* API با Bearer token، rate limit اتمی در دیتابیس موجود، مقایسهٔ ثابت‌زمانی و IP پراکسیِ صریحاً مورداعتماد محافظت می‌شود.
* CORS wildcard حذف شده است؛ کلاینت Python سروربه‌سرور است و نیازی به CORS ندارد.
* تماس با Telegram روی HTTPS انجام می‌شود، SSL verify روشن و redirect غیرفعال است.
* وب‌هوک POST هدر `X-Telegram-Bot-Api-Secret-Token` را اجباری بررسی می‌کند؛ update تکراری یک‌بار پردازش می‌شود.
* URL رسانه باید HTTPS و مقصد عمومی باشد؛ مقصد محلی/خصوصی و redirect ناامن رد می‌شوند؛ اندازهٔ فایل محدود است.
* کانال و Health عمومی جزئیات نسخه/محیط هاست را افشا نمی‌کنند.
