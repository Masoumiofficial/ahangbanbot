# بازبینی و گزارش تست — v1.3.0

تاریخ بررسی: 2026-10-19

## کارهای انجام‌شده

- ارسال فایل رسانه‌ای: ابتدا URL واقعی به Bot API داده می‌شود؛ اگر تلگرام نتواند آن را دریافت کند، وب‌هوک فایل HTTPS عمومی را با بررسی redirect و سقف ۴۹ MiB موقتاً می‌گیرد و با cURL به‌صورت multipart بارگذاری می‌کند. مسیر ویدیو/آلبوم از ارسال صوت جداست. برای فایل صوتی موفق `file_id` cache می‌شود. در شکست، فقط دکمهٔ منبع اصلی و صفحهٔ واقعی اثر نمایش داده می‌شود.
- پنل `/admin` و دکمهٔ ادمین: آمار، سلامت، پاک‌سازی کش با تأیید، راهنمای مسدودسازی/رفع مسدودی و پیام همگانیِ پیش‌نمایش‌دار.
- state کاربر/آمار/صف پیام همگانی در جدول‌های افزونه در **همان دیتابیس وردپرس** است؛ دادهٔ آهنگ/خواننده همچنان فقط از WordPress می‌آید. برای پیام همگانی از WP-Cron دسته‌ای استفاده می‌شود.
- POST وب‌هوک با Secret جاری اجباری احراز می‌شود؛ update تکراری، payload بیش‌ازحد، و خطای پردازش مدیریت می‌شوند.
- چند خطای مرزی اصلاح شد: سازگاری PHP 7.4 (حذف `str_starts_with`)، اسم ادمین HTML-escape، بازگشت Home از پیام عکس، صفحه‌بندی query با callback کوتاه، ID عددی هنرمند و حفظ توکن با فیلد خالی.
- حالت Python نیز مرور شد: rate-limit/block قبلاً تعریف شده بود ولی در handlerها ثبت نشده بود؛ اکنون pre-dispatch guard فعال است. مسدودکردن شناسهٔ هنوز ثبت‌نشده کار می‌کند. ارسال رسانه fallback امنِ دانلود/آپلود دارد و پنل ادمین inline ارائه شده است.

## شواهد تست در محیط توسعه

| بررسی | نتیجه |
|---|---|
| `python3 -m py_compile` برای همهٔ فایل‌های Python | ✅ موفق |
| `python3 -m pytest -q` | ✅ ۱۹ تست موفق |
| ساخت PTB Application با توکن/کلید ساختگی فقط برای ساخت handlerها (بدون درخواست شبکه) | ✅ ۴۱ handler در گروه اصلی + guard گروه -۱ |
| بررسی نحوی PHP با `php-parser` و گرامر PHP 7.4 | ✅ هر ۸ فایل PHP بدون خطای parse |
| `php -l` واقعی | ⚠️ در محیط توسعه PHP CLI نصب نیست؛ بنابراین runtime/lint خود PHP اجرا نشد |
| سایت WordPress و Bot API واقعی، ارسال یک MP3 واقعی از هاست | ⏳ نیازمند تست زنده با سایت/توکن و یک فایل واقعی |

> تست‌های خودکار تضمین نمی‌کنند که همهٔ لینک‌های رسانهٔ ahangban.ir از شبکهٔ سرور قابل دریافت باشند. این وابسته به SSL، DNS، خروجی HTTPS، cURL، محدودیت حجم/زمان هاست و وضعیت همان فایل است.

## چک‌لیست پذیرش زنده

1. افزونه v1.3.0 را نصب کنید و `/start` و `/admin` را بزنید.
2. از پنل ادمین آمار، سلامت و پاک‌سازی cache را آزمایش کنید.
3. روی یک فایل MP3 واقعی ۱۲۸ یا ۳۲۰ بزنید؛ انتظار: audio در تلگرام یا fallback با پیوند واقعی. سپس همان کیفیت را دوباره بزنید تا cache `file_id` استفاده شود.
4. یک ویدیو/آلبوم واقعی را آزمایش کنید.
5. ادمین یک شناسهٔ آزمایشی واقعی را `/block ID` کند و `/unblock ID` را بررسی کند.
6. پیام همگانی را فقط با مخاطبان موافق/تست انجام دهید؛ تأیید/لغو و اجرای WP-Cron را بررسی کنید.
7. در صورت شکست ارسال، خطای امن به کاربر می‌آید؛ در لاگ PHP فقط روش/status و توضیح کوتاه ثبت می‌شود، نه URL حاوی توکن Bot API.

## محدودیت شناخته‌شده

پیام همگانی در webhook با WP-Cron دسته‌ای ادامه پیدا می‌کند. اگر WP-Cron در تنظیمات هاست خاموش باشد یا سایت بازدید نداشته باشد، صف تا درخواست بعدی سایت متوقف می‌ماند. این موضوع روی پاسخ‌های معمول ربات و ارسال مستقیم آهنگ اثر ندارد.
