# آزمایش polling سریع‌تر WordPress — نسخهٔ 1.6.5

## تغییر این نسخه

در نسخهٔ 1.6.4 رویداد دریافت Telegram هر ۶۰ ثانیه زمان‌بندی می‌شد؛ بنابراین فرمانی که درست پس از یک poll می‌رسید، ممکن بود تا اجرای بعدی Cron منتظر بماند. نسخهٔ 1.6.5 رویداد WP-Cron را هر **۳۰ ثانیه** زمان‌بندی می‌کند و هنگام ارتقا، زمان‌بندی یک‌دقیقه‌ای قبلی را با زمان‌بندی جدید جایگزین می‌کند. اندازهٔ batch همچنان حداکثر دو update است تا اجرای PHP کوتاه بماند.

**برای رسیدن به پاسخ زیر یک دقیقه، Cron Job خود هاست نیز باید `wp-cron.php?doing_wp_cron` را هر ۳۰ ثانیه اجرا کند.** اگر DirectAdmin یا میزبان فقط فاصلهٔ یک‌دقیقه‌ای را می‌پذیرد، polling همچنان کار می‌کند اما تأخیر تا حدود یک دقیقه باقی می‌ماند؛ به‌روزرسانی افزونه به‌تنهایی cadence هاست را تغییر نمی‌دهد.

## مراحل آزمایش بدون Terminal

1. ZIP نسخهٔ 1.6.5 را از WordPress → افزونه‌ها جایگزین کنید و فعال‌بودن افزونه را بررسی کنید.
2. در DirectAdmin → **Cron Jobs** از پشتیبانی هاست بپرسید آیا می‌توانند `https://ahangban.ir/wp-cron.php?doing_wp_cron` را هر ۳۰ ثانیه فراخوانی کنند. اگر بله، همان را تنظیم کنند. اگر حداقل فاصلهٔ پنل یک دقیقه است، job دقیقه‌ای را نگه دارید و انتظار پاسخ زیر ۳۰ ثانیه نداشته باشید.
3. در پیشخوان → **آهنگ‌بان API** بررسی کنید حالت **polling زمان‌بندی‌شدهٔ WordPress** انتخاب شده و وب‌هوک ثبت نیست. دکمهٔ «ثبت وب‌هوک» را نزنید و Python polling دیگری را هم‌زمان اجرا نکنید.
4. بعد از آنکه زمان آخرین polling تازه شد، یک بار `/start` بفرستید و زمان پاسخ را یادداشت کنید. آزمایش را سه بار با فاصله تکرار کنید؛ هنگام backlog ممکن است چند بازه لازم باشد.
5. اگر تأخیر نزدیک ۳۰ ثانیه است، Cron سی‌ثانیه‌ای احتمالاً عمل می‌کند. اگر پاسخ‌ها نزدیک ۶۰ ثانیه‌اند، cadence واقعی Cron احتمالاً دقیقه‌ای است. اگر از ۹۰ ثانیه گذشت یا پاسخ نیامد، «آزمون اتصال و وضعیت» را باز کنید و آخرین زمان اجرا، آخرین دریافت موفق، خطای polling و صف را ثبت کنید.

## تصمیم بعد از آزمایش

- **پاسخ می‌آید اما حدود یک دقیقه طول می‌کشد:** ابتدا از پشتیبانی تأیید بگیرید که job واقعاً هر ۳۰ ثانیه اجرا می‌شود؛ اگر چنین قابلیتی ندارند، polling روی این هاست زیر یک دقیقه نمی‌شود.
- **آخرین poll تازه است ولی `getUpdates` خطا دارد:** درخواست خروجی HTTPS از PHP به `api.telegram.org` یا ثبت‌بودن وب‌هوک را بررسی کنید.
- **poll تازه و موفق است اما `/start` پاسخی نمی‌گیرد یا بیش از ۹۰ ثانیه طول می‌کشد:** مشکل دیگر فقط فاصلهٔ Cron نیست؛ زمان‌بندی worker/صف یا پردازش PHP را بررسی کنید.
- اگر زیر یک دقیقه ممکن نشد و پاسخ سریع لازم است، گزینه‌های بعدی این است که پشتیبانی هاست مسیر ورودی وب‌هوک Telegram را اصلاح کند یا Python polling روی VPS اجرا شود. تا انتخاب نهایی، برای یک Bot Token فقط یک دریافت‌کننده فعال باشد.
