# راهنمای DirectAdmin و WordPress — افزونه v1.6.2

این راهنما برای WordPress روی هاست اشتراکی است. وب‌هوک PHP بدون اجرای دائمی Python پیام‌های Telegram را می‌گیرد. از نسخهٔ **1.5.2** اگر handler هاست (از جمله LSAPI) امکان تعریف env برای PHP را ندهد، می‌توان اعتبارنامه‌ها را از فرم اختصاصی پیشخوان وارد کرد؛ فایل `.env` ربات Python همچنان به‌طور خودکار توسط PHP خوانده نمی‌شود. نسخهٔ **1.5.3** قالب کپشن کانال و Voice Note را اضافه کرد؛ نسخهٔ **1.6.0** کنترل متن‌های ربات، صفحه‌بندی و منوی شروع را افزود؛ نسخهٔ **1.6.1** ارسال امن به Telegram را با HTTP API ثابت اصلاح کرد. نسخهٔ **1.6.2** fallback ویس را فقط برای Python polling و فقط در وضعیت `unavailable`/`failed` فعال می‌کند؛ webhook PHP مستقل است.

## تشخیص اتصال و تنظیم رفتار ربات (v1.6.2)

در 1.6.1 درخواست‌های API ثابت Telegram از HTTP API معمول WordPress استفاده می‌کنند، نه `wp_safe_remote_post`؛ مقصد فقط `api.telegram.org` است، Token/متد اعتبارسنجی می‌شوند، TLS روشن است و redirect دنبال نمی‌شود. اگر پس از ارتقا خطای DNS، cURL، SSL یا مسدودبودن درخواست دیدید، همان جزئیات پالایش‌شده را برای پشتیبانی هاست بفرستید.

در «آهنگ‌بان API»، دکمهٔ **آزمون اتصال و وضعیت وب‌هوک** بدون ارسال پیام، `getMe` و `getWebhookInfo` را می‌خواند. اگر اتصال شکست بخورد، جزئیات فنی WordPress/cURL/SSL یا پاسخ HTTP تلگرام در اعلان پیشخوان نمایش داده می‌شود؛ توکن و Secret از خطا حذف می‌شوند. اگر ثبت وب‌هوک شکست خورد، همین جزئیات را برای پشتیبانی هاست ارسال کنید.

کارت «رفتار و تجربهٔ کاربری ربات» متن سادهٔ `/start` و `/help`، تعداد نتایج در هر صفحه و نمایش دکمه‌های منوی شروع را کنترل می‌کند. کارت کانال نیز اجازه می‌دهد پیش‌نمایش ویس را روشن/خاموش کنید، مدت ۱۵ تا ۶۰ ثانیه انتخاب کنید و متن تکمیلی کپشن را تعیین کنید. خالی‌گذاشتن متن‌های شروع/راهنما از متن پیش‌فرض استفاده می‌کند. تنظیمات متن/منو برای ربات PHP در حالت وب‌هوک است؛ تنظیمات کانال و preview در مسیرهای WordPress نیز اعمال می‌شوند.

## اعتبارنامه‌ها و ارتقا

نسخهٔ 1.5.0 در اولین اجرا Secretهای قدیمی را از `wp_options` حذف می‌کرد. اگر سایت قبلاً به v1.5.0 یا v1.5.1 ارتقا یافته، بعد از نصب v1.5.2 باید مقدارها را دوباره در فرم «اعتبارنامه‌های API و تلگرام» وارد کنید. از v1.5.2 محیط PHP اولویت دارد؛ در نبود env افزونه از مقدارهای واردشده در فرم استفاده می‌کند.

| نام | مقدار |
|---|---|
| `AHANGBAN_API_TOKEN` | دقیقاً ۶۴ رقم hex؛ اگر Python polling از API استفاده می‌کند، با مقدار همین نام در `.env` آن یکی باشد |
| `AHANGBAN_BOT_TOKEN` | توکن BotFather برای همین ربات |
| `AHANGBAN_BOT_SECRET` | Secret مجزای وب‌هوک؛ ۱ تا ۲۵۶ نویسه از `A-Z a-z 0-9 _ -`؛ ۶۴ رقم hex توصیه می‌شود |
| `AHANGBAN_TRUSTED_PROXY_IPS` | اختیاری؛ IP یا CIDR پراکسی‌های مورد اعتماد، با کاما جدا شود |

برای ساخت دو مقدار تصادفی مستقل روی دستگاه امن، اجرا کنید: `python3 -c "import secrets; print(secrets.token_hex(32))"`؛ برای API token و webhook secret جداگانه اجرا شود. در فرم افزونه، فیلدهای رمزواژه مقدار را دوباره نشان نمی‌دهند و خالی‌گذاشتن آن‌ها مقدار قبلی را حفظ می‌کند.

**هشدار امنیتی:** در روش فرم، Secretها در `wp_options` دیتابیس WordPress ذخیره می‌شوند و رمزنگاری‌شده نیستند؛ بکاپ دیتابیس را محرمانه نگه دارید. تنظیم env در PHP امن‌تر است. Secretها را در Git، گفت‌وگوی عمومی، URL یا لاگ نگذارید.

## ۱) نصب افزونه

1. فایل ZIP نسخهٔ نصب را از لینک نسخهٔ جاری در `README.md` دانلود کنید.
2. WordPress → افزونه‌ها → افزودن افزونه → بارگذاری افزونه؛ ZIP را انتخاب و نصب/جایگزین کنید. در File Manager می‌توان آن را در `wp-content/plugins` بارگذاری و Extract کرد.
3. WordPress → افزونه‌ها → فعال‌سازی/به‌روزرسانی **AhangBan Connector**.
4. پیشخوان → **آهنگ‌بان API** را باز کنید. اگر وضعیت اعتبارنامه‌ها «نیازمند تنظیم» است، توکن‌ها را در فرم «اعتبارنامه‌های API و تلگرام» وارد کنید؛ مقدار هیچ Secretی پس از ذخیره نمایش داده نمی‌شود.

## ۲) تنظیمات غیرحساس

در همان صفحه می‌توانید شناسهٔ ادمین تلگرام، یوزرنیم ربات، حالت اجرا و تنظیم کانال را ثبت کنید. برای این راهنمای هاست اشتراکی، حالت **وب‌هوک WordPress** را انتخاب کنید؛ گزینهٔ Python polling فقط برای سرویس جدا روی VPS است و وب‌هوک و polling را برای یک Bot Token هم‌زمان فعال نگذارید. این گزینه‌ها Secret نیستند. برای یافتن شناسهٔ عددی Telegram از `@userinfobot` استفاده کنید.

برای polling روی VPS، `.env.example` را به `.env` خصوصی کپی کنید؛ مقدار `AHANGBAN_API_TOKEN` باید دقیقاً با محیط PHP یکی باشد. `BOT_TOKEN` همان توکن BotFather است. مطمئن شوید `.env` در Git نباشد.

## ۳) ثبت وب‌هوک

1. در پنل WordPress حالت اجرا را روی **وب‌هوک** بگذارید.
2. در صورت نبود env، سه مقدار را از فرم افزونه ذخیره کنید و مطمئن شوید وضعیت API token، Bot token و Secret «پیکربندی شده» است.
3. SSL معتبر HTTPS را برای دامنه فعال کنید.
4. روی «ثبت وب‌هوک در تلگرام» بزنید؛ افزونه `setWebhook` را با Bot Token و Secret موجود فراخوانی می‌کند. بازکردن مسیر وب‌هوک در مرورگر فقط GET را آزمایش می‌کند و آن را ثبت نمی‌کند.
5. در تلگرام به ربات `/start` بفرستید. `/ping` فقط پاسخ عمومی می‌دهد و جزئیات نسخهٔ PHP/WordPress را افشا نمی‌کند.
6. Health عمومی: `https://ahangban.ir/wp-json/ahangban/v1/health`؛ پاسخ مورد انتظار فقط `{"status":"ok"}` است.

فیلدهای رمزواژه پس از ذخیره خالی می‌مانند. اگر توکن یا Secret را عوض کردید، دوباره وب‌هوک را ثبت کنید تا Telegram همان Secret تازه را بفرستد.

## ۴) ارسال فایل و رسانه

1. ابتدا Telegram سعی می‌کند فایل را از URL واقعیِ ذخیره‌شده برای همان اثر دریافت کند.
2. در صورت رد قطعی Telegram، افزونه فقط URL HTTPS با مقصد عمومی را بررسی می‌کند، حداکثر ۴۹ MiB را به فایل موقت می‌گیرد و در صورت فعال‌بودن cURL بارگذاری می‌کند.
3. اتصال HTTP به Telegram redirect را دنبال نمی‌کند؛ چون Bot Token در مسیر API قرار دارد.
4. اگر پاسخ ارسال مبهم (timeout/5xx) باشد، همان فایل کورکورانه دوباره فرستاده نمی‌شود؛ پیام جایگزین، پیوند واقعی منبع و صفحهٔ اثر را نشان می‌دهد.
5. اگر هاست نتواند فایل را امن دریافت/آپلود کند، ربات پیوند واقعی می‌دهد؛ فایل نمونه یا URL ساختگی ساخته نمی‌شود.

## ۵) اتصال کانال و انتشار (اختیاری)

1. ربات را در کانال به‌عنوان مدیر با مجوز ارسال پیام اضافه کنید.
2. در پیشخوان → «اتصال کانال»، `@username` عمومی یا شناسهٔ `-100…` را وارد و ذخیره کنید.
3. «ارسال پیام آزمایشی» یک پیام واقعی در کانال منتشر می‌کند.
4. کپشن کانال از داده‌های واقعی WordPress ساخته می‌شود: نام خواننده، نام آهنگ، هشتگ از تاکسونومی هنرمند، لینک صفحهٔ رسمی و `@Ahangban_ir`. نام‌ها ترجمه یا آوانویسی ساختگی نمی‌شوند.
5. پست و ویس reply هر دو همان دو دکمهٔ شیشه‌ای را دارند: «مشاهده و دریافت در ربات» و «صفحهٔ آهنگ در سایت». لینک ربات به مسیر دانلود کامل آهنگ می‌رود؛ ویس فقط نمونه است.
6. برای webhook PHP، WordPress پس از انتشار کارت، نمونهٔ تنظیم‌شده در پنل (۱۵ تا ۶۰ ثانیه) از `music128` (و در نبود آن `music320`) را به‌صورت Voice Note و reply از مسیر WP-Cron می‌فرستد؛ فایل کامل به‌جای نمونه ارسال نمی‌شود.
7. این مسیر PHP به `proc_open` فعال و FFmpeg دارای encoder `libopus` در محیط PHP نیاز دارد. وضعیت را در کارت «وضعیت سامانه» پیشخوان → «آهنگ‌بان API» ببینید؛ اگر Terminal ندارید، از پشتیبانی هاست بپرسید آیا FFmpeg/libopus و `proc_open` در LSAPI قابل استفاده‌اند. در صورت نیاز پشتیبانی می‌تواند مسیر باینری را با ثابت اختیاری `AHANGBAN_FFMPEG_PATH` در `wp-config.php` تنظیم کند.
8. در Python polling، اگر endpoint انتشار دستی وضعیت `queued` برگرداند، bot دومین ویس نمی‌فرستد؛ فقط `unavailable` یا `failed` باعث می‌شود خود Python یک‌بار با FFmpeg/libopus نصب‌شده در کانتینر از منبع واقعی تبدیل و ارسال کند. اگر Python هم نتواند، پیام خطا می‌دهد؛ نتیجهٔ مبهم Telegram retry نمی‌شود. این fallback در webhook PHP اجرا نمی‌شود.
9. برای مسیر PHP، WP-Cron یا Cron Job هاست باید فعال باشد؛ برای deep-link یوزرنیم ربات را ثبت کنید.

## ۶) پنل مدیریت Telegram

ادمین پس از `/start` دکمهٔ مدیریت را می‌بیند یا `/admin` می‌فرستد. امکانات: آمار، سلامت، پاک‌سازی cache، فهرست صفحه‌بندی‌شدهٔ کاربران با ID عددی و وضعیت مسدودی، دستورات `/block` و `/unblock`، broadcast با پیش‌نمایش و تأیید، و انتشار دستی پست به کانال.

در Python bot، کاربر با دکمهٔ ❤️ روی کارت آهنگ آن را می‌پسندد؛ پسندها و فهرست شخصی در SQLite ربات می‌مانند، ولی عنوان/اطلاعات هر آهنگ از API وردپرس می‌آید. هنرمند با `term_id` واقعی دنبال/لغو می‌شود و فهرست شخصی در ربات دیده می‌شود؛ اعلان خودکار انتشار در این MVP وجود ندارد.

انتشار دستی کانال با افزونهٔ **v1.5.1 یا جدیدتر** کار می‌کند؛ برای fallback Voice Note باید افزونهٔ **v1.6.2** و کد Python جدید مستقر باشند. در Python polling از جست‌وجو/جدیدترین‌ها/محبوب‌ها کارت اثر را باز کنید، «انتشار در کانال» و سپس تأیید را بزنید. مقصد از تنظیم WordPress می‌آید؛ انتشار دستی حتی با خاموش‌بودن انتشار خودکار فعال است. تنظیم جداگانه یا Secret جدیدی در `.env` لازم نیست؛ همان Bot Token باید در Python و در دسترس افزونهٔ WordPress باشد. Broadcast همچنان batch و WP-Cron است؛ تأیید دوبارهٔ preview مصرف‌شده رد می‌شود.

فقط شناسهٔ Telegram و آمار ضروری در جدول‌های افزونه در **همان دیتابیس WordPress** نگه‌داری می‌شوند؛ دادهٔ نوشته/هنرمند به دیتابیس دیگر منتقل نمی‌شود. برای جزئیات نگه‌داری دادهٔ تعاملی و بکاپ، سیاست حریم خصوصی سایت را به‌روز کنید.

## نکات امنیتی و عیب‌یابی

- API درخواست‌ها با `Authorization: Bearer ...` محافظت و نرخ با شمارندهٔ اتمی محدود می‌شود. مقدار پیش‌فرض IP از `REMOTE_ADDR` می‌آید.
- اگر WordPress پشت reverse proxy است، `AHANGBAN_TRUSTED_PROXY_IPS` را فقط با IP/CIDR واقعی پراکسی تنظیم کنید؛ هدرهای `X-Forwarded-For` از کلاینت ناشناس قابل جعل‌اند.
- افزونه برای REST هیچ CORS wildcardای نمی‌فرستد؛ API برای ارتباط سروربه‌سرور است.
- **ربات پاسخ نمی‌دهد:** وضعیت سه اعتبارنامه را در پنل WordPress بررسی کنید، وب‌هوک را ثبت کنید و لاگ PHP را ببینید.
- **Webhook 403 می‌دهد:** Secret ذخیره‌شده/محیطی را بررسی کنید؛ پس از هر تغییر، وب‌هوک را دوباره ثبت کنید.
- **Health 404/HTML است:** افزونه فعال باشد و مسیر REST توسط افزونهٔ امنیتی/هاست مسدود نشده باشد.
- **Broadcast در صف می‌ماند:** WP-Cron فعال باشد و بازدید/درخواست سایت یا Cron Job اجرا شود.
- اتصال زنده به هاست، Telegram یا WP-Cron از محیط توسعه قابل تأیید نیست؛ تست نصب و ارسال واقعی باید روی سایت انجام شود.
