# راهنمای DirectAdmin و WordPress — افزونه v1.5.0

این راهنما برای WordPress روی هاست اشتراکی است. وب‌هوک PHP می‌تواند بدون اجرای دائمی Python پیام‌های Telegram را بگیرد؛ اما **Secretها باید در محیط پردازش PHP قابل‌دسترسی باشند**. قابلیت تعریف متغیر محیطی در DirectAdmin به نوع PHP handler و تنظیم هاست بستگی دارد و باید از پنل/پشتیبانی هاست تأیید شود. فایل `.env` ربات Python توسط PHP خودکار خوانده نمی‌شود.

## پیش از ارتقا از v1.4.0

در v1.5.0، اولین اجرای افزونه گزینه‌های قدیمی توکن API، Bot Token و Webhook Secret را از `wp_options` حذف می‌کند و دیگر از آن‌ها fallback نمی‌گیرد. برای جلوگیری از قطع سرویس، ابتدا مقادیر را در محیط PHP و در صورت استفاده از Python در `.env` خصوصی آن تنظیم کنید؛ سپس افزونه را ارتقا دهید.

متغیرهای لازم برای webhook در محیط PHP:

| نام | مقدار |
|---|---|
| `AHANGBAN_API_TOKEN` | مقدار تصادفیِ دقیقاً ۶۴ رقم hex؛ باید با مقدار همین نام در `.env` Python یکی باشد |
| `AHANGBAN_BOT_TOKEN` | توکن BotFather |
| `AHANGBAN_BOT_SECRET` | Secret مجزای webhook، ۱ تا ۲۵۶ نویسه از `A-Z a-z 0-9 _ -`؛ ۶۴ رقم hex توصیه می‌شود |
| `AHANGBAN_TRUSTED_PROXY_IPS` | اختیاری؛ IP یا CIDR پراکسی‌های مورد اعتماد، با کاما جدا شود |

مقدار تصادفی را خارج از هاست و روی دستگاه امن بسازید، مثلاً با `python3 -c "import secrets; print(secrets.token_hex(32))"`. Secret واقعی را در Git، گفت‌وگو، URL، فرم تنظیمات WordPress یا لاگ قرار ندهید. این مخزن فقط `.env.example` شامل placeholder دارد.

اگر هاست در DirectAdmin امکان تزریق env به PHP-FPM ندارد، از پشتیبانی بخواهید متغیرها را در pool مربوط به دامنه تنظیم کند. راه‌حل `SetEnv`، `.htaccess` یا فایل `.env` فقط وقتی قابل استفاده است که پیکربندی فعلی هاست صریحاً تضمین کند PHP-FPM آن را امن و درست می‌خواند؛ رفتار آن را حدس نزنید. اگر میزبان env را پشتیبانی نمی‌کند، از WordPress webhook با v1.5.0 استفاده نکنید؛ Python را روی VPS اجرا کنید و از مدیر هاست برای یک روش امنِ تزریق `AHANGBAN_API_TOKEN` به PHP کمک بگیرید.

## ۱) نصب افزونه

1. فایل ZIP نسخهٔ نصب را از لینک نسخهٔ جاری در `README.md` دانلود کنید.
2. WordPress → افزونه‌ها → افزودن افزونه → بارگذاری افزونه؛ ZIP را انتخاب و نصب/جایگزین کنید. در File Manager می‌توان آن را در `wp-content/plugins` بارگذاری و Extract کرد.
3. WordPress → افزونه‌ها → فعال‌سازی/به‌روزرسانی **AhangBan Connector**.
4. پیشخوان → **آهنگ‌بان API** را باز کنید. بخش «وضعیت سامانه» آماده‌بودن API token، Bot token و Webhook Secret را نشان می‌دهد، ولی مقدار هیچ Secretی را نمایش نمی‌دهد.

## ۲) تنظیمات غیرحساس

در همان صفحه می‌توانید شناسهٔ ادمین تلگرام، یوزرنیم ربات، حالت اجرا و تنظیم کانال را ثبت کنید. برای این راهنمای هاست اشتراکی، حالت **وب‌هوک WordPress** را انتخاب کنید؛ گزینهٔ Python polling فقط برای سرویس جدا روی VPS است و وب‌هوک و polling را برای یک Bot Token هم‌زمان فعال نگذارید. این گزینه‌ها Secret نیستند. برای یافتن شناسهٔ عددی Telegram از `@userinfobot` استفاده کنید.

برای polling روی VPS، `.env.example` را به `.env` خصوصی کپی کنید؛ مقدار `AHANGBAN_API_TOKEN` باید دقیقاً با محیط PHP یکی باشد. `BOT_TOKEN` همان توکن BotFather است. مطمئن شوید `.env` در Git نباشد.

## ۳) ثبت وب‌هوک

1. در پنل WordPress حالت اجرا را روی **وب‌هوک** بگذارید و مطمئن شوید هر سه env لازم در PHP فعال‌اند.
2. SSL معتبر HTTPS را برای دامنه فعال کنید.
3. روی «ثبت وب‌هوک در تلگرام» بزنید؛ افزونه `setWebhook` را با Secret محیط PHP اجرا می‌کند.
4. در تلگرام به ربات `/start` بفرستید. `/ping` فقط پاسخ عمومی می‌دهد و جزئیات نسخهٔ PHP/WordPress را افشا نمی‌کند.
5. Health عمومی: `https://ahangban.ir/wp-json/ahangban/v1/health`؛ پاسخ مورد انتظار فقط `{"status":"ok"}` است.

مقدار واقعی Secret در صفحه چاپ نمی‌شود. اگر متغیرها را عوض کردید، دوباره webhook را ثبت کنید تا همان Secret جدید در Telegram قرار بگیرد.

## ۴) ارسال فایل و رسانه

1. ابتدا Telegram سعی می‌کند فایل را از URL واقعیِ ذخیره‌شده برای همان اثر دریافت کند.
2. در صورت رد قطعی Telegram، افزونه فقط URL HTTPS با مقصد عمومی را بررسی می‌کند، حداکثر ۴۹ MiB را به فایل موقت می‌گیرد و در صورت فعال‌بودن cURL بارگذاری می‌کند.
3. اتصال HTTP به Telegram redirect را دنبال نمی‌کند؛ چون Bot Token در مسیر API قرار دارد.
4. اگر پاسخ ارسال مبهم (timeout/5xx) باشد، همان فایل کورکورانه دوباره فرستاده نمی‌شود؛ پیام جایگزین، پیوند واقعی منبع و صفحهٔ اثر را نشان می‌دهد.
5. اگر هاست نتواند فایل را امن دریافت/آپلود کند، ربات پیوند واقعی می‌دهد؛ فایل نمونه یا URL ساختگی ساخته نمی‌شود.

## ۵) اتصال کانال و انتشار خودکار (اختیاری)

1. ربات را در کانال به‌عنوان مدیر با مجوز ارسال پیام اضافه کنید.
2. در پیشخوان → «اتصال کانال»، `@username` عمومی یا شناسهٔ `-100…` را وارد و ذخیره کنید.
3. «ارسال پیام آزمایشی» یک پیام واقعی در کانال منتشر می‌کند.
4. فقط پس از موفقیت تست، انتشار خودکار را روشن کنید. فقط آثار موسیقی تازهٔ قابل‌تشخیص از داده‌های موجود WordPress وارد صف می‌شوند؛ نوشته‌های عادی نادیده گرفته می‌شوند.
5. WP-Cron یا Cron Job هاست باید فعال باشد. برای deep-link، یوزرنیم ربات را ثبت کنید.

## ۶) پنل مدیریت Telegram

ادمین پس از `/start` دکمهٔ مدیریت را می‌بیند یا `/admin` می‌فرستد. امکانات: آمار حداقلی، سلامت، پاک‌سازی cache، مسدود/آزادکردن شناسه و broadcast با پیش‌نمایش و تأیید. Broadcast به‌صورت batch با WP-Cron اجرا می‌شود؛ برای جلوگیری از ارسال تکراری، تأیید دوبارهٔ همان preview رد می‌شود.

فقط شناسهٔ Telegram و آمار ضروری در جدول‌های افزونه در **همان دیتابیس WordPress** نگه‌داری می‌شوند؛ دادهٔ نوشته/هنرمند به دیتابیس دیگر منتقل نمی‌شود. برای جزئیات نگه‌داری دادهٔ تعاملی و بکاپ، سیاست حریم خصوصی سایت را به‌روز کنید.

## نکات امنیتی و عیب‌یابی

- API درخواست‌ها با `Authorization: Bearer ...` محافظت و نرخ با شمارندهٔ اتمی محدود می‌شود. مقدار پیش‌فرض IP از `REMOTE_ADDR` می‌آید.
- اگر WordPress پشت reverse proxy است، `AHANGBAN_TRUSTED_PROXY_IPS` را فقط با IP/CIDR واقعی پراکسی تنظیم کنید؛ هدرهای `X-Forwarded-For` از کلاینت ناشناس قابل جعل‌اند.
- افزونه برای REST هیچ CORS wildcardای نمی‌فرستد؛ API برای ارتباط سروربه‌سرور است.
- **ربات پاسخ نمی‌دهد:** وضعیت envهای PHP و لاگ PHP را با مدیر هاست بررسی کنید؛ token قدیمی دیتابیس دیگر fallback نیست.
- **Webhook 403 می‌دهد:** Secret محیط PHP را بررسی و webhook را دوباره ثبت کنید.
- **Health 404/HTML است:** افزونه فعال باشد و مسیر REST توسط افزونهٔ امنیتی/هاست مسدود نشده باشد.
- **Broadcast در صف می‌ماند:** WP-Cron فعال باشد و بازدید/درخواست سایت یا Cron Job اجرا شود.
- اتصال زنده به هاست، Telegram یا WP-Cron از محیط توسعه قابل تأیید نیست؛ تست نصب و ارسال واقعی باید روی سایت انجام شود.
