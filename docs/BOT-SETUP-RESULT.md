## نتیجهٔ پیاده‌سازی

- نام استاندارد توکن Python برابر `TELEGRAM_BOT_TOKEN` است؛ `BOT_TOKEN` برای استقرارهای قدیمی همچنان alias سازگار است. توکن در کد ثابت نشده و در log یا پیام کاربر چاپ نمی‌شود.
- `TARA_API_BASE` قابل تنظیم است و در حالت معمول از `AHANGBAN_API_BASE` به مسیر حساب `https://ahangban.ir/wp-json/tara/v1` مشتق می‌شود.
- درخواست‌های API فقط با HTTPS پذیرفته می‌شوند، redirect دنبال نمی‌شود و هدر درخواست شامل `User-Agent: AhangBanBot/1.0` است. `telegram_id` پیش از ارسال باید عدد صحیح مثبت باشد.
- health از `/tara/v1/health` بدون `Authorization` خوانده می‌شود؛ پاسخ واقعی قالب `ok: true` است و کلاینت آن را برای سازگاری با `/ping` به `status: ok` نرمال می‌کند. مقدار `linked` در health وضعیت تنظیم‌بودن توکن API است، نه اتصال تلگرام کاربر.
- اتصال با کد ۸کاراکتریِ یک‌بارمصرفی انجام می‌شود که کاربر از صفحهٔ حساب سایت می‌گیرد و **به‌صورت پیام متنی عادی در گفتگوی خصوصی ربات** می‌فرستد. ارسال کد در گروه رد می‌شود. کد به `/start` یا deep link تبدیل نمی‌شود؛ مسیر قبلی `/start song_<id>` برای بازکردن آهنگ همچنان برقرار است.
- دستورها: `/me` خلاصهٔ حساب، `/saved` شمارندهٔ پسندیده‌های سایت، `/follows` خوانندگان دنبال‌شدهٔ سایت، `/latest` یا `/feed` فید تازه‌های آن‌ها، و `/unlink` قطع اتصال. این فرمان‌ها فقط در گفتگوی خصوصی پاسخ حسابی می‌دهند. `/new` همچنان برای جدیدترین آثار عمومی سایت است.
- خطای احراز هویت/پیکربندی در log سرور با وضعیت و کد خطا ثبت می‌شود و به کاربر پیام عمومی داده می‌شود. متن خطای خام یا مقدار secret در این پیام‌ها چاپ نمی‌شود؛ خطای کلی ربات نیز متن exception را log نمی‌کند.
- عملیات تغییردهندهٔ موجود در API client با retry خاموش اجرا می‌شوند تا مصرف دوبارهٔ کد یک‌بارمصرف یا mutation مبهم تکرار نشود؛ کش همان حساب پس از mutation پاک می‌شود.

## قرارداد API قالب که مبنای کلاینت است

| روش و مسیر | کاربرد | احراز هویت |
|---|---|---|
| `GET /wp-json/tara/v1/health` | سلامت عمومی قالب؛ پاسخ شامل `ok`, `site`, `version`, `account`, `linked` است. | عمومی؛ بدون توکن |
| `POST /wp-json/tara/v1/link` | بدنه: `code`, `telegram_id`, `username`, `first_name` | `Authorization: Bearer …` |
| `GET /wp-json/tara/v1/me?telegram_id=…` | خلاصهٔ حساب و شمارنده‌ها | Bearer |
| `POST /wp-json/tara/v1/unlink` | بدنه: `telegram_id` | Bearer |
| `GET /wp-json/tara/v1/follows?telegram_id=…` | فهرست هنرمندان دنبال‌شده | Bearer |
| `GET /wp-json/tara/v1/feed?telegram_id=…&since=…&limit=…` | تازه‌های هنرمندان دنبال‌شده | Bearer |

در tag بررسی‌شده، routeهای حساب زیر `tara/v1` هستند، چون کلاس `AhangBan_API` در افزونه وجود دارد. توکن معتبر باید در تنظیم قالب (گزینهٔ `tg_token`) یا تنظیم افزونهٔ Connector (`ahangban_connector_token`) موجود باشد و با `AHANGBAN_API_TOKEN` محیط Python یکسان باشد.

### محدودیت مهم `/saved`

خلاصهٔ `/me` مقدار `counts.likes` را می‌دهد، اما source قالب routeای برای دریافت فهرست آهنگ‌های پسندیده‌شده ارائه نمی‌کند. بنابراین `/saved` فقط تعداد و پیوند حساب سایت را نشان می‌دهد؛ فهرست ساختگی یا پسندهای SQLite محلی را به‌جای دادهٔ وردپرس نمایش نمی‌دهد. پسندها و دنبال‌کردن‌های محلی فعلی ربات با حساب WordPress یکی نشده‌اند و هیچ تغییری برای یکی‌کردن شمارنده‌ها انجام نشده است. ارائهٔ فهرست واقعی `/saved` به API جدید سمت قالب نیاز دارد و در این تغییر عمداً انجام نشد.

## تنظیم لازم برای استقرار

در تنظیمات محیطی خصوصی AbrhaPaaS یا محل اجرای Python، نام‌ها را تنظیم کنید؛ مقدار واقعی توکن را در فایل Git، log یا گفتگو قرار ندهید:

```env
TELEGRAM_BOT_TOKEN=<توکن محرمانهٔ BotFather>
AHANGBAN_API_BASE=https://ahangban.ir/wp-json/ahangban/v1
AHANGBAN_API_TOKEN=<همان secret شصت‌وچهاررقمی hex تنظیم‌شده در WordPress>
ADMIN_IDS=<شناسه‌های عددی ادمین، در صورت نیاز>
# اختیاری؛ در حالت معمول از AHANGBAN_API_BASE مشتق می‌شود:
# TARA_API_BASE=https://ahangban.ir/wp-json/tara/v1
```

پیش از استفاده، باید مطمئن شد حساب Taranehyar و قابلیت‌های لازم در قالب فعال‌اند و توکن ۶۴رقمی در تنظیمات WordPress با مقدار محیط Python یکسان است؛ این تنظیمات و استقرار زنده در دسترس این بررسی نبودند. برای یک Bot Token، polling پایتون و webhook وردپرس را هم‌زمان اجرا نکنید؛ هنگام جابه‌جایی حالت اجرا، منبع قبلی دریافت updateها باید متوقف شود تا تعارض `getUpdates`/webhook پیش نیاید.

پس از استقرار، روش کاربر این است: وارد حساب سایت شود، کد ۸کاراکتری را از پنل حساب بردارد، آن را در گفتگوی خصوصی با ربات به‌صورت متن بفرستد و سپس `/me` را امتحان کند. کد تولیدشدهٔ قالب یک‌بارمصرف و دارای زمان انقضاست؛ عمر پیش‌فرض در source بررسی‌شده ۶۰۰ ثانیه است. اگر تلگرام قبلاً به حساب دیگری وصل است، ابتدا `/unlink` و سپس اتصال مجدد لازم است.

## آزمون‌ها و راستی‌آزمایی

آزمون‌های زیر در محیط محلی و با mock اجرا شدند؛ هیچ درخواست زنده‌ای به WordPress، Telegram یا AbrhaPaaS ارسال نشد.

- `pytest -q bot/tests` — **۹۶ passed**؛ فقط warning مربوط به تنظیم‌نشدن scope پیش‌فرض fixture در `pytest-asyncio` نمایش داده شد.
- `compileall` برای `bot`, `app.py` و `main.py` — موفق.
- Ruff با انتخاب `E4,E7,E9,F` روی فایل‌های Python تغییرکرده — موفق.
- `git diff --check` — موفق.
- اسکن همان انتخاب Ruff روی کل محدودهٔ قدیمی پروژه، علاوه بر فایل‌های تغییرکرده، **۱۲ مورد از قبل موجود** در `bot/handlers/browse.py`, `bot/handlers/search.py` و تست‌های قدیمی را نشان می‌دهد؛ این فایل‌ها در این کار تغییر نکرده‌اند.

**این نتیجه اثبات نمی‌کند که کاربر واقعی به حساب سایت وصل شده یا deployment جدید فعال است.** برای تأیید زنده باید تنظیم محیط AbrhaPaaS، نسخهٔ واقعاً نصب‌شدهٔ قالب/افزونه، دسترسی HTTPS و یک کد واقعیِ تازه در محیط امنِ خود سایت آزمایش شود. در این محیط به آن تنظیمات و secretها دسترسی نداشتیم و هیچ موفقیت زنده‌ای ادعا نمی‌شود.
